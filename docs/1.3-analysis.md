# Task 1.3: My Assessment of the AI Critique

The critique ([1.3-ai-critique.md](1.3-ai-critique.md)) reviewed SPEC v1.1 and returned 42 findings. I took the 18 that change the schema, its guarantees, or its scope one at a time, checked each against the spec text, and decided it before the spec was edited. The other 24 are accounted for at the end.

## Where I agree

The critique was strongest where the spec claimed a guarantee the database did not enforce.

- **X1.** Permissive switcher policies combined with OR into every tenant read of `org_memberships`, the table that drives authorization. They are gone. The switcher runs on a dedicated role that reads only the caller's memberships.
- **X2.** `users` had no row-level security, and the API role could update identity columns. Both are fixed. Identity columns change only through a separate identity role.
- **C1, C2, C6.** A status flip to open failed on departed assignees. A task could land in an archived status through a race. `closed_at` could show a stale date. Each has a fix and a test (T18, T7, T3).
- **C3.** Concurrent edits could record a stale `from` value. Updates now return `OLD` and `NEW` from the saving statement.
- **C4, X3, I1, and the task-number half of X6.** Cheap and correct: one snapshot per read request, capped pages and query cost, an index for every sort, and task numbers assigned only by the database.

## Where I disagree

- **F1.** I kept re-key by transfer as the design instead of a key-history table, then moved re-key out of v1, because the brief never asks for it.
- **F3.** Letting the brief's viewer edit tasks is a product choice. I renamed the role contributor so its name matches what it does. A read-only role is one enum value later.
- **C5.** The critique assumed undated tasks. That is a product decision, not a schema fact. Every task carries a due date, so no sort key is null.
- **S1, S3, F6.** Partitioning `tasks` is premature at 10M rows. Per-column rank would force a new rank on every cross-column drop. The database roles carry the isolation story, so they stay, and roles with no v1 workload move to Later with their features.
- **X6 role changes, X4.** Role changes stay API-only. Wrapping context calls in subqueries is a review rule, not a CI check. Both are recorded risks.

## N+1 risks

N2 and N3 describe discipline the spec already requires. Every nested field reachable from a list goes through a request-scoped DataLoader, and the request reads the caller's membership once, so `authorize` never queries. N1 is bounded, not removed. The X3 cost limit charges nested connections, but a page of tasks that asks for timelines still runs one timeline query per task.

## What it missed

1. **Lost domain events.** Events emitted after commit are lost on a crash between commit and emit. The fix is a transactional outbox, shipped with mutations.
2. **Per-row project lookups.** The overdue check looked up the project for every candidate task. Inactive project ids are now read once per request (T27).
3. **Its own inputs.** It cited DDL from SPEC v1.0, which v1.1 did not contain. About a third of its findings could not be checked against the document under review, so none was accepted without verification.

## What I would fix first, and why

| Rank | Finding | Why |
|---|---|---|
| 1 | X1 | Authorization reads the membership table. A leak there makes every other check unreliable. |
| 2 | X2 | One resolver bug on a global table means account takeover across tenants. |
| 3 | C3 | History is never migrated. A wrong `from` value is wrong forever. |
| 4 | C1, C2 | A false database guarantee is worse than a documented gap. |
| 5 | X3 | One request could exhaust the database. The fix is validation only. |
| 6 | I1 | The unindexed default order is the first query to fail under the Part 3 load. |

My order differs from the AI's in one place. C3 moves above C1, C2, X3, and I1. Those can be fixed later without lasting damage. A wrong history entry cannot be repaired after it is written.

## The other 24 findings

- **Covered above:** N2, N3, and F5, which the scope cut in F8 resolved.
- **No longer apply:** C9, F2, X8, and I3. Re-key, org deletion, and auto-archive moved to Later.
- **Open, no v1 decision:** N1, C7, C8, C10, S2, S4 to S8, X5, X7, I2, I4, I5, F4, and F7. S2, S4, and S6 wait for load-test numbers, as the critique suggested.
